# 程式設計情境桌遊：太空船維修

面向對程式設計有興趣的國、高中生，以十大維修關卡接觸入門程式概念的單人網頁遊戲。

目前階段：第一版可玩原型完成，第一至十關各有四項維修任務與場景回饋。支援角色移動、碰撞、十關依序維修、通關與重玩，第十關包含最終安全驗證與返航倒數。

首次遊玩依序呈現 01 背景故事、02 介面導覽、03 角色移動、04 首次抵達故障設備。按「開始維修」成功開啟第一關後，顯示 05 教學完成的四句 AI 台詞與正式開始提示。可逐段閱讀、返回，或按「進入任務」／Esc 直接開始作答。

第一關題目右側的「▤ 維修手冊」預設展開：可看四個觀念與語法範例，或逐步展開當題提示 1／2，也可自行收合。同題正式答錯兩次後可查看診斷提示；本版依使用者決定先不加入掃描卡。提示進度與答錯次數會保留，完整重玩時重置。第一關完成後，維修路線下方可開啟觀念回顧。

## 本機啟動

使用 Node.js 24，首次執行 `npm ci`，接著執行 `npm run dev`，開啟終端顯示的網址。

正式模式：先執行 `npm run build`，再執行 `npm start`，預設網址為 `http://localhost:3000`。正式服務支援環境變數 `PORT`。

## 操作

- 開場以「下一段／上一段」閱讀，最後按「進入探索者號」；「略過開場」或 Esc 接續介面導覽。導覽結束後介紹 WASD；可逐段閱讀或略過說明，開始移動後依三角形與地圖提示前往主控制電腦。底部「介面導覽」可隨時重看，保留目前進度。
- 首次抵達時自動暫停並顯示 AI 說明，最後按「開始維修」。Esc／「稍後維修」返回探索，之後在互動範圍內點擊主控制電腦即可接續原段落；不重播全部故事，不反覆自動彈窗。成功開題後，本局恢復一般設備互動。
- 教學完成紀錄保存在本機瀏覽器；重新整理或回訪直接進入遊戲，維修進度仍從 0/10 開始。通關後「重新開始」會清除完成紀錄並重播完整教學。瀏覽器停用儲存時，本局仍可完成教學與遊戲，回訪可能再次出現教學。
- WASD 或方向鍵移動；紅色船員為玩家，採用 Among Us 風格的手繪 SVG 外觀，包含背包、護目鏡與走路踏步。左右移動會轉向，停下、卡牆或開啟維修面板時停止踏步；腳底碰撞位置維持原設定。
- 預設為放大 3.4 倍的角色跟隨視角，只看見附近船艙；按 M 或「全船地圖」切換全覽，再按一次返回。
- 目前故障點使用黃色三角形標記；在畫面外時，邊緣會出現指向該位置的小三角形。提示代表方向，仍需沿通道前進。
- 沿船內走廊靠近金色數字標記，再點擊標記開啟維修面板。
- 第一關修復警報系統，第二關設定發電機，第三關修復能源計算，第四關修復氣閘安全判斷，第五關修復冷卻迴圈，第六關修復推力函式，第七關追蹤貨箱串列，第八關修復船員字典查詢與授權，第九關修復雷達例外處理，第十關重建躍遷安全邏輯；各完成四項任務後通關。第十關還須完成導航準備、實際狀態檢查與三秒倒數，才會顯示返航成功。
- Esc 或右上角關閉控制可關閉面板，不會完成維修。
- 十關完成後可重新開始。重新整理頁面也會重置進度。
- 第一版以電腦鍵盤、滑鼠遊玩，尚未提供觸控控制。
- 地圖右上「顯示碰撞範圍」可切換目前的 hitbox：綠色為地板，紅色為障礙，未上色區域也不可走；藍圈為角色實際碰撞大小。移動滑鼠會顯示該位置是否可站立及 F／O 區域編號。網址加上 `?hitbox=1` 可直接開啟這個模式，方便標示問題位置。
- 要直接查看完整碰撞圖，可使用 `?hitbox=1&view=overview`；碰撞疊圖與滑鼠座標同時支援兩種視角。

## 驗證

- `npm test`：關卡流程、遠距限制、重複結算、碰撞與十站可達性。
- `npm run build`：型別檢查及正式建置。
- 首次瀏覽器驗證先執行 `npx playwright install chromium`，再執行 `npm run test:browser`。
- 瀏覽器測試透過實際鍵盤事件走完十關，檢查面板、縮放、進度與重玩；不使用傳送或直接修改遊戲狀態。
- [第一版驗證紀錄](第一版驗證紀錄.md)。

## GitHub Pages 部署（目前使用）

遊戲網址：<https://persids-py.github.io/Designing-Tabletop-Games-for-Programming-Education/>

第一次需在儲存庫 Settings → Pages → Build and deployment 將 Source 設為 GitHub Actions。之後每次推送 `main`，工作流程會執行測試、建置、完整瀏覽器驗證，全部通過後自動上傳 `dist/` 並部署。

這一版為靜態網頁，不需要 Railway 或常駐 Node 伺服器。`npm start` 的伺服器保留供本機測試與其他部署方式使用。Vite 使用相對路徑，確保地圖、CSS、JavaScript 與首頁連結在專案子目錄正常載入。

## Railway 部署（舊設定，保留備用）

儲存庫包含 `railway.json`，設定建置、正式啟動與 `/health` 健康檢查。Railway 服務根目錄使用儲存庫根目錄，連接 `main` 分支。

推送後查看 Deployments：成功後到 Settings → Networking 產生公開網址。服務使用 Railway 提供的 `PORT` 並監聽 `0.0.0.0`，產生網域時使用相同的服務連接埠。

GitHub Actions 會執行流程測試、正式建置與完整瀏覽器測試。若要等檢查通過才部署，在 Railway 啟用 Wait for CI。GitHub 推送成功與 Railway 上線成功需分別確認。

第一關需走到三個設備完成指令單選、符號填空、廣播字串修改，再到警報啟動台排列程式卡片。修好後可見藍色螢幕、閃爍紅燈與廣播波紋，最終通過後房間轉綠，解鎖第二關。詳細內容見 [第一關設計](第一關設計.md)。

第二關需將賦值積木排成正確指令、修正備用變數名稱、讓電壓顯示器讀取變數，最後預測供電輸出。通過後黃色能源核心發光，電壓表顯示 220V、110V，解鎖維生系統室。詳細內容見 [第二關設計](第二關設計.md)。

第三關需修正主能源字串轉型、選擇消耗運算子、修復備用能源計算，再填入可用能源算式。三個綠色能源槽會隨修復亮起，驗證整數 155 後解鎖氣閘艙。詳細內容見 [第三關設計](第三關設計.md)。

第四關需補冒號、調整四空格縮排、完成 else 開門指令，再判斷 120／100／80 kPa 的輸出。三組測試通過後按「解除封鎖」，壓力警示解除、艙門燈轉綠，解鎖第五關。詳細內容見 [第四關設計](第四關設計.md)。

第五關需找出無窮迴圈原因、設定每輪降溫量、補上循環計數指令，再預測四次溫度、次數與結束溫度。驗證通過後藍色冷卻液恢復流動，溫度從 100°C 降至 60°C、風扇恢復，解鎖第六關。詳細見 [第五關設計](第五關設計.md)。

第六關需補函式宣告冒號、修正乘法運算子、把顯示指令改為回傳，再依序測試速度 0、10、20 的推力 0、30、60。每次通過點亮一盞能源燈，三組全過後恢復藍色推進光束並解鎖第七關。詳細見 [第六關設計](第六關設計.md)。

第七關依序移除受損貨箱、修正讀取索引、插入備用物資，最後確認四箱順序與工具箱輸出。貨箱會重新排列，機械手臂領取 D 工具箱出庫，解鎖第八關。詳細見 [第七關設計](第七關設計.md)。

第八關需修正工程師字典鍵、讀取 level、使用 get() 查詢不存在角色，再驗證最低等級 2 及三種角色的授權。通過後全像投影顯示 Chen／LEVEL 2 與授權完成，解鎖第九關。詳細見 [第八關設計](第八關設計.md)。

第九關需辨識 ValueError、放置 try／except 積木、分類五組訊號與計算總和，再修復錯誤計數器。一般資料輸出 50／2，全雜訊輸出 0／2；通過後綠色雷達恢復掃描、干擾消失，解鎖第十關。詳細見 [第九關設計](第九關設計.md)。

第十關需修正導航字典鍵、人工授權布林判斷與安全邏輯，再通過四組測試。實際導航仍未就緒，必須返回導航控制器完成準備，回到啟動台檢查狀態後啟動三秒倒數；關閉面板會取消倒數，成功後顯示「探索者號返航成功」。詳細見 [第十關設計](第十關設計.md)。
